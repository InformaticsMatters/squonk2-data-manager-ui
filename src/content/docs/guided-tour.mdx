# Guided tour

This page walks through the Squonk Data Manager from logging in to reading a result. More detailed
descriptions can be found in the individual [how-to guides](/docs/how-to) referred to along the way.

## Logging in

To do anything useful in the Squonk Data Manager you must log in and be authenticated. Do this using
the **Account** menu in the top right corner and clicking **Login**. You are taken to Keycloak where
you authenticate, and, assuming you are successful, you are taken back to the Data Manager where you
can perform your work.

When finished use the **Logout** option in the same **Account** menu.

More details can be found in the [Logging in](/docs/how-to/login) guide.

## The shell you land in

Once signed in, the masthead shows the **organisation** you are working as, and the main navigation
offers the three workspaces: **Projects**, **Datasets** and **Administration**.

The organisation is the one thing about where you are that is remembered between visits. Changing it
takes you Home first, so nothing is ever shown under an organisation it does not belong to.

If you have no project of your own yet, the **Projects** index offers to get you one: it explains
the hierarchy, creates your **personal unit**, and hands you to project creation. See
[Getting started](/docs/how-to/getting-started).

## Choosing a project

Choose **Projects** in the main navigation. This opens a searchable index of the projects you can
reach in your current organisation. Each row states the project, the **unit** that contains it, the
highest role you hold in it, and whether it is private. Selecting one opens that project's **Files**.

The project you are working in is always the one in the address bar, so the page, its data and the
link you can share always agree, and returning to the index is how you move to another project.
Once you are in a project, the strip below the masthead names it and offers its four sections.

More details can be found in the [Projects](/docs/how-to/projects) guide.

## Files

This shows the contents (files and directories) in your project. The interface is a simple file
browser a bit like Windows Explorer and probably doesn't need much explanation. Note that the
operations you can perform here are quite limited. If you want full control we suggest you run a
Jupyter notebook in your project and use the file manager of the Jupyter Lab interface, or a command
line console, to perform your operations.

Everything you run has full access to these project contents. See the
[Files](/docs/how-to/projects/files) guide.

## Run

This is where you launch **workflows**, **applications** and **jobs** to do your work. Whatever you
launch runs in the project in the address bar.

What is available (defined by the system administrator) is displayed as cards. Each card states the
kind of definition it is, how many times it has run in this project, and — for a job — which version
it is offering. Use **Filter** to show only **Workflows**, **Applications** or **Jobs**, and the
search field to narrow by name or keyword.

To run something, click its **Run** button. A dialog appears letting you define the inputs and
options: _inputs_ are project files that form the input, and _options_ are the parameters for the
execution. Specify these and click **Run**. A successful launch opens what it created under
**Results**, so you can follow the work that was actually started.

See the [Run](/docs/how-to/projects/run) guide for more details.

## Results

This shows what you have launched in the project you are in, and nothing from any other project. A
high level summary of each result is presented along with the ability to drill down into the
specific details.

Details include the status and any events that were generated. You are also able to view the input
and output files and any log files that were created.

When you are finished, remember to terminate a running application or job to free up the resources
it is using.

See the [Results](/docs/how-to/projects/results) guide for more details.

## Manage

A project's **Manage** section states the project's facts and holds the changes you can make to it:
the roles you hold, its coin usage, the people who can reach it, its privacy, what you can do in it,
its identifiers, and — for its creator — its deletion.

**Manage** is available to everyone who can see the project, so you can always read a project's
details even where you cannot change anything. See the [Manage](/docs/how-to/projects/manage) guide.

## Datasets

**Datasets** is one of the three workspaces, alongside **Projects** and **Administration**. It lists
every dataset you can reach, without you having to choose a unit first; a unit is asked for only as
billing context when you upload. From a dataset version you can attach it to a project, add a new
version, or view its contents. See the [Datasets](/docs/how-to/datasets) guide.

## Administration

**Administration** is available to every signed-in user. Its rail lists the organisation in effect —
with **Overview**, **Charges** and **Usage & Inventory** — and beneath that every unit of that
organisation, searchable. Choosing a unit opens its **Access**, **Subscriptions**, **Charges** and
**Usage & Inventory**.

What you can change there depends on your role. Ordinary actions you cannot use are disabled with a
reason rather than removed, so it is clear what relationship or role a task requires; actions that
only a platform administrator can ever take are hidden instead. Where a read is refused outright,
the page keeps what it can show and says which part is missing.

See the [Administration](/docs/how-to/administration) guide.
