## Choosing where you work - a How To guide

Most activity in Squonk Data Manager happens inside a **project**. The project you are working in is
always the one in the address bar: there is no separate context to set, and no project, unit,
dataset or filter is remembered between visits. Your current **organisation** is remembered, because
it is the identity the application is shown under. This means the page you are looking at, the data
it shows, and the link you can share with a colleague always agree.

### Choosing a project

Choose **Projects** in the main navigation. This opens a searchable index of the projects you can
reach in your current **organisation**, with the **unit** each one belongs to shown alongside it so
that projects sharing a name can be told apart.

Selecting a project opens its **Files**, and the project's name, unit and organisation stay visible
while you work in it. A project workspace has four sections:

- **Files** - browse, upload and manage the project's files.
- **Run** - find and launch applications, jobs and workflows.
- **Results** - follow what you have launched.
- **Manage** - project details, privacy, members, usage and deletion.

To work in a different project, return to the **Projects** index and choose it. There is no selector
that swaps the project underneath a page you already have open.

### Organisations and units

Your current **organisation** is shown as the application's identity. Changing it takes you Home
first, so that content is never shown under an organisation it does not belong to. Opening a project
that belongs to another organisation adopts that organisation before the project appears.

A **unit** is billing context rather than something you browse in. It decides who pays for a project
or a dataset upload, so you choose one while creating a project or uploading a new dataset, and not
at any other time. See the [concepts document](/docs/concepts) for a description of these concepts.

If you are not a member of a **unit** in a named **organisation** you can still create a project in
the **Default** organisation, where you have a **personal unit** named after your username. Personal
units are designed primarily for your own private use, though you can still make your projects
public or add other people to your project so that you can collaborate.

### Managing organisations and units

Organisation and unit membership, privacy defaults, subscriptions, charges, and usage reports all
live under **Administration**, which is available to every signed-in user. What you can change there
depends on your role: ordinary actions you cannot use are disabled with a reason rather than
removed, while actions only a platform administrator can ever take are hidden.

Owners of an **organisation** can create a new **unit** within it if you want a different work space
(e.g. research group, department etc.). The **Default** **organisation** cannot have **units** added
to it other than a user's **personal** unit.
